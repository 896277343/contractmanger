# 外贸合同管理（首版）

当前首版提供账号登录、逐份 OA HTML 导入、合同及多产品明细维护、签订/发货/收款口径汇总，以及按原工作簿 38 列顺序导出 `.xlsx`。看板右上角“导出当前范围”使用当前业务员、年份、业绩口径、日期及下钻筛选；文件另含“筛选说明”页。当前合同编辑和审核入口为 Django 管理后台。看板支持全部/我的/各业务员、年份、签订/发货/收款口径、自定义日期筛选；提供原币金额卡、月度趋势、执行进度、国家/客户/产品等结构分布、客户排行及合同明细下钻。更完整的 Vue 编辑界面仍待开发。

看板支持按合同号、客户、OA 流水号和产品型号搜索。人民币总计按当前业绩口径逐笔计算：签订使用合同金额，发货使用本次发货金额，收款使用本次收款金额；每笔先乘适用汇率并四舍五入到分，再求和。人民币汇率为 1；美元、欧元未填汇率时分别使用标准预估汇率 7、7.5。签订及发货优先使用合同结算汇率；收款优先使用收款记录的汇率，若币种与合同相同再使用合同汇率。看板分别标出实际汇率、标准预估汇率、无需换算及缺少金额的笔数。待收款按每份合同的“合同原币金额 × (1 − 执行进度)”计算，再按合同汇率折人民币；执行进度 1 表示已收 100%，0.5 表示已收 50%。未填或不在 0～1 范围的进度不计入待收，并在看板提示数量。实际收款金额仍按收款记录单独展示，跨币种收款单列。
点击人民币总计、汇率来源笔数、人民币/美元/欧元等原币金额卡和币种构成可下钻至对应合同，明细展示当前业绩口径的原币金额、折人民币金额及汇率来源。月度趋势默认“全部折美元”：将各笔已折人民币金额按月相加，再统一除以 7 得到美元等值；点击柱子可查看该月参与计算的合同。缺少金额或无法识别币种的记录不计入折算总计，可点击相应笔数查看。
回款情况、执行快览和执行进度分布中的数字与条目也可点击下钻；回款明细显示同币种已收、待收或跨币种记录，逾期与开票明细显示对应日期，进度明细显示执行详情。

历史数据可由管理员或信息处理员在 `/import-excel/` 上传 xlsx。系统自动识别合同数据表和表头，预览合同与金额后确认导入。已有合同不覆盖业务数据，只补充缺失的 OA 流程。一个单元格出现多个合同编号时跳过该组，先在源表拆分。当前样例为 56 个产品行、26 组合同，其中 1 组有两个合同号，会导入其余 25 组。

OA HTML 导入按合同编号识别已有合同。OA 导入只关联流程号，并从“供货信息”补入物料编码、名称、规格、数量、单位、技术参数等；不会向 Line items 新增产品行，也不会改动 Excel 导入的产品行。重复上传同一 OA 文件不会重复新增物料。物料按合同保存并记录来源 OA，源文件没有提供明确产品归属时不自动关联到具体产品。可在管理后台的合同详情查看和编辑物料。

OA 上传支持单份 HTML 或包含单份 OA HTML 与 `files` 附件目录的 ZIP；系统只读取 HTML，不保存附件。OA“已发货信息”中的物料编码、出库单据编号、数量等单独保存为出库物料记录，不自动生成发货金额。按当前范围导出的工作簿保留原 38 列“合同明细”，另附“OA供货物料”“OA已发货物料”“发货记录”三张表，均可按合同编号追溯。

更新日志位于 `/logs/`，业务员可查看自己合同的操作记录，领导和信息处理员可查看全部。后台编辑会记录合同字段与产品、物料、流程、发货、收款明细的新增、修改、删除及字段前后值；OA 导入记录新增流程和物料编码，历史 Excel 导入及审核操作也会留痕。合同后台详情页下方可直接查看对应日志。

业务员角色拥有其名下合同的物料、OA 已发货物料与更新日志查看权限，也可在后台维护合同物料和出库明细；信息处理员可维护全部，领导可查看全部。角色权限随数据库迁移补齐。
合同与 OA 流程是多对多关系：一份合同可以关联多个流程，一个流程也可以覆盖多个合同。历史 Excel 同一合同号的多行、或一个单元格中的多个 OA 流水号，会合并到该合同。已有合同再次导入时只补充缺失的流程关联，不重复导入产品；同一合同内不会重复关联相同流水号。

## 本地启动

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
New-Item -ItemType Directory -Force data
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver
```

访问 `http://127.0.0.1:8000/`。在后台创建用户，设置 `is_staff` 并分配“业务员”“信息处理员”或“领导”组。业务员需 `is_staff` 才能进入合同编辑后台。上传 OA 时以当前登录账号作为业务员，请按真实归属登录导入。合同列表中可批量“提交审核”“审核通过”或“退回补录”。

局域网临时测试时，在 PowerShell 中先设置 `$env:DJANGO_ALLOWED_HOSTS='localhost,127.0.0.1,你的局域网IP'`，然后运行 `python manage.py runserver 0.0.0.0:8000`，从其他设备访问 `http://你的局域网IP:8000/`。若仍无法连接，检查 Windows 防火墙是否允许该端口及两台设备是否处于可互通的网络。此方式仅用于局域网开发测试。

合同金额按合同存一次；CSV 为每个产品一行，因此同一合同金额在多行重复显示，**不得直接对该列求和计算业绩**。有多次发货/收款时，现阶段在对应单元格以分号列出各次记录。看板按合同、发货记录或收款记录汇总，避免重复计算多产品合同。

## VPS 部署要点

使用环境变量设置 `DJANGO_SECRET_KEY`、`DJANGO_ALLOWED_HOSTS`（域名或公网 IP）、`DJANGO_CSRF_TRUSTED_ORIGINS`（如 `https://你的域名`）、`DJANGO_HTTPS=1`、`DJANGO_DEBUG=0`。HTTPS 由可信反向代理终止，代理必须覆盖传给 Django 的 `X-Forwarded-Proto`，应用进程只监听本机地址，不得使用 `runserver`。配置 `STATIC_ROOT` 后运行 `python manage.py collectstatic --noinput`，静态文件交给代理提供。上线前用生产环境变量运行 `python manage.py check --deploy`。SQLite 文件默认在 `data/contracts.sqlite3`，仅应用账号可读写。定期使用 SQLite 在线备份命令备份数据库，备份复制到 VPS 之外并验证恢复。

备份命令：`python scripts/backup_sqlite.py /path/to/backups`。建议至少每周自动运行一次，另保留年度归档，并把备份复制到 VPS 之外。原 OA HTML 不持久保存，只存文件名和 SHA-256 摘要。

## 代码版本更新

GitHub 仓库只保存代码。`data/`（含 SQLite 数据库与备份）、`.env`、虚拟环境和静态文件收集目录均被 Git 忽略；生产数据库仍保存在 VPS，单独备份。

本地完成修改后，双击 `scripts/publish.cmd`，或在 PowerShell 运行 `./scripts/publish.ps1 "本次修改说明"`。脚本只暂存项目代码、检查提交内容、提交并推送到 `origin`。

服务器首次接入 Git 仓库后，使用 `sudo bash /opt/contractmanger/scripts/update_server.sh` 更新。脚本先备份当前 SQLite 数据库，然后只快进拉取 `main`，安装依赖、执行迁移、收集静态文件并重启 `contractmanger` 服务；不会从 GitHub 下载或覆盖数据库。当前手动上传的服务器目录在首次接入 Git 时需单独处理，不能直接对现有目录运行 `git reset --hard`。
